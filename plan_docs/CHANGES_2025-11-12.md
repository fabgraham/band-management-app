## 2. Delete Functionality Troubleshooting 🔧

### Issue Discovery
**Problem**: Delete buttons for setlists and songs not working properly on web (localhost:8081)

### Multiple Approaches Tried

#### Approach 1: Using `Alert.alert()` directly
- **Result**: No dialog appears on web platform
- **Root Cause**: React Native's `Alert.alert()` is not implemented for web

#### Approach 2: Using `window.confirm()`
- **Result**: Items deleted immediately without waiting for confirmation
- **Root Cause**: Expo's web environment returns `{}` (empty object) instead of boolean
- **Evidence**: Console logs showed `type: object value: {}` instead of `type: boolean`
- **Behavior**: Empty object is truthy, so `if (!confirmed)` evaluated incorrectly

#### Approach 3: Back to `Alert.alert()` with button callbacks
- **Result**: Buttons not responding at all
- **Status**: Issue documented for future resolution

## Technical Learnings

### React Native Web Limitations
- `Alert.alert()` doesn't work on web - need cross-platform alternative
- `window.confirm()` is polyfilled by Expo and returns objects instead of booleans
- Need to use platform-specific code or libraries for web compatibility

### Event Handling in React Native
- Nested Pressables can cause event bubbling issues
- Use `stopPropagation()` to prevent parent handlers from firing
- Add proper hitSlop and padding for better touch targets

### Database Best Practices
- Column naming consistency between database and TypeScript is critical
- Map database columns to TypeScript properties in service layer
- Use unique constraints carefully - consider use cases before adding
